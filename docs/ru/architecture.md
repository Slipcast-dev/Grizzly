# Архитектура

Grizzly — две реализации одного замысла: нативное приложение для macOS и порт на Electron для Windows. Общие у
них таблицы переводов и правила типов файлов, но не код.

```
Sources/Grizzly/          приложение macOS (SwiftUI, ~9 тыс. строк)
  App/        AppState (вкладки, черновики, теги, уведомления), Settings, Theme, `UpdateManager` (проверка, загрузка, установка), точка входа и команды меню
  Core/       Модель документа, загрузка и кодировки, парсер Markdown, CSV, подсветка (`SyntaxEngine` разбирает комментарии и строки между строками файла, `Syntax` красит по теме), поиск, `Updater` (разбор релиза, версии, контрольные суммы), `AppPatch` / `BinaryDelta` (патчи обновления: только изменённые файлы, бинарники дельтой), `RichFormat` (команды форматирования как правки текста), `InlineMarkup`, `Attachments`, `FontLibrary` (встроенные шрифты)
  Features/   Вкладки, панели с перетаскиваемой границей, редактор (`EditorView`, `LiveTextView`: режим «Пользователь» прячет код форматирования через `LiveStyler` и рисует маркеры, таблицы и вложения в `LiveLayoutManager`; «Разработчик» — `MarkdownStyler` и колонка номеров строк), панель и меню форматирования, вложения, поиск, боковая панель с тегами, настройки (стекло, шрифт интерфейса), уведомления
  Render/     Таблица CSV
  Library/    Виртуальная библиотека (папки / избранное / теги) и история открытых файлов в JSON
QuickLook/    Расширение Quick Look (.appex): HTML-превью Markdown, CSV, YAML и логов;
              использует Core/FileLoader, FileType, CSVTable и MarkdownParser
resources/    Иконка, Localizable.strings (ru, en) и fonts/ (16 семейств под лицензией SIL OFL)
electron/     Порт для Windows
  main.js       Главный процесс: окно, меню, файловый ввод-вывод, проверка орфографии, передача файлов второму запуску, каталог данных
  updater.js    Проверка релиза, загрузка, контрольная сумма и скрипт подмены portable-exe
  preload.js    Узкий мост для рендерера (contextIsolation)
  renderer/     Интерфейс на чистом JS/CSS: state, core (парсеры), ui
scripts/      build-app.sh, make-dmg.sh, make-patch.sh, test.sh
tests/        Swift-тест (swiftc) и JS-тесты (node --test); VERSION — единый источник версии
samples/      По файлу каждого поддерживаемого типа для ручной проверки
```

## Поток данных

1. Приходит URL файла (диалог, перетаскивание, командная строка).
2. `FileLoader` декодирует его — UTF-8, UTF-8 BOM, UTF-16 BOM, затем Windows-1251 и ISO-8859-1 — и запоминает
   кодировку, чтобы сохранение было обратимым.
3. `FileType` по расширению определяет тип; `Document` строит представление (таблица CSV или
   строки с подсветкой).
4. Каждая панель показывает документ в своём режиме (текст всегда тот же Markdown файла; «Пользователь» только прячет и перерисовывает код форматирования); `Search` находит совпадения, панели их подсвечивают.
5. После обновления из приложения оно сохраняет вкладки, панели, режим и позицию прокрутки (UserDefaults на macOS, `session.json` на Windows), перезапускается и один раз восстанавливает их; запись старше десяти минут игнорируется.
6. Наблюдатель за файлом замечает изменения на диске; панель показывает плашку и никогда молча не затирает несохранённую правку.

## Модель безопасности

- Единственный сетевой код — проверка обновлений: GET на `api.github.com/repos/Slipcast-dev/Grizzly/releases/latest` при запуске и из настроек. Загрузки принимаются только с `github.com` / `*.githubusercontent.com` по HTTPS, должны совпасть с SHA-256 из описания релиза (релиз без суммы отклоняется), ограничены по размеру, каждый редирект должен оставаться на GitHub, и устанавливаются только после решения по несохранённым правкам. Телеметрии нет.
- HTML-файлы показываются как исходный текст, не отрисовываются и не выполняются.
- Рендерер Electron: `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false` и
  Content-Security-Policy `default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; object-src 'none'; base-uri 'none'; form-action 'none'`.
  Доступ к файлам — в главном процессе через мост preload. Страница не может запрашивать разрешения устройства, DevTools в собранном приложении отключены.
- Каждый IPC-обработчик Electron отвечает только собственной странице приложения. Файловый IPC принимает только абсолютные пути с поддерживаемыми расширениями; запись дополнительно ограничена файлами, которые пользователь открыл, создал или выбрал в диалоге; файлы больше 100 МБ не читаются.
- Библиотека хранит только ссылки (пути) и теги. Единственная операция, которая меняет файлы, — «Переименовать тег» / «Удалить тег»: она переписывает `#тег` в их тексте после подтверждения (файлы RTF и файлы с несохранёнными правками пропускаются).
- Релизные сборки не подписаны (или подписаны ad-hoc); целостность подтверждается опубликованными суммами SHA-256.

## Локализация

`resources/{ru,en}.lproj/Localizable.strings` содержат строки интерфейса. Русские ключи служат исходным текстом;
порт Electron получает `strings-en.json` из английского файла командой `npm run strings`.
